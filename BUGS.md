# Известные баги

## `HexPairToByte`: верхняя граница `'f'` у младшей цифры проверяется по старшей

- Файл: `mySys.pas`, функция `HexPairToByte`.
- Суть: в ассемблерной проверке строчной **младшей** цифры (`AH`) верхняя
  граница `'f'` сравнивалась со **старшей** цифрой (`AL`) вместо младшей
  (`AH`) — на строке 210 стояло `CMP AL, 'f'` вместо `CMP AH, 'f'`.
- Из-за этого младшая цифра `'g'..'z'` не отсекается как некорректная (если
  старшая цифра не больше `'f'`) и функция возвращает мусорное ненулевое
  значение вместо `0`. Например, пара `"4g"` даёт `$50`, а не `0`.
- Поведение намеренно сохранено при переводе функции на Pascal: в ветке
  `(L >= Byte('a'))` условие проверяет `H <= Byte('f')` вместо
  `L <= Byte('f')`.

## `--lua`/`--endlua`: маркеры Lua-блока сравниваются без обрезки пробелов

- Файл: `uScanThread.pas`, цикл `TScanThread.Execute`.
- Суть: маркер открытия блока распознаётся точным сравнением всей строки
  `S := AnsiLowerCase(Self.Line)` с `'--lua'`/`'-- lua'` (строки 2790–2791), а
  закрывающий — с `'--endlua'`/`'-- endlua'` (строки 2818–2819), без `Trim`.
- Из-за этого строка с ведущими или хвостовыми пробелами (отступ, таб) не
  распознаётся как маркер и уходит в общий разбор команд, где в `else`-ветке
  процедуры `ExecScriptCommand` (строки 21759–21771) выдаётся
  `Неопознанная команда: --lua`. Обычные команды при этом хвостовые пробелы
  срезают (строки 2852–2855).
- Статус: не исправлено.

## `size("")`: падение на пустой строке (обращение `V[0]`)

- Файл: `uScanThread.pas`, функция `size` (case 76, строки 10120–10213).
- Суть: при извлечении аргумента первый цикл обрезки (строки 10150–10151)
  проверяет `Length(V) > 0`, а второй (строки 10152–10153) —
  `while not (V[Length(V)] in ([']'] + gWordCharsadq)) do Delete(V, Length(V), 1)`
  — без проверки длины. Для пустого аргумента `size("")` после снятия кавычек
  `V = ''` и `V[Length(V)]` обращается к `V[0]`, что на пустой (nil) AnsiString
  даёт access violation и валит весь скрипт.
- Тот же небезопасный паттерн «первый while с guard, второй без» встречается и в
  других функциях (`setlayout` 10263–10265, `setselectedtext` 10340 и др.), но
  подтверждено падение пока только для `size("")`.
- Следствие: тест `test_size_empty` в `tests/integration/strings_tests.txt` вынесен
  в хвост после сводки и не вызывается автоматически.
- Статус: не исправлено.

## `get clipboard %a`: слова кладутся в столбцы, а не в строки массива

- Файл: `uScanThread.pas`, ветка `else` разбора `get clipboard` (строки 18097–18112).
- Суть: при разбивке буфера обмена по словам (`get clipboard %a` без модификаторов
  или `get clipboard word %a`) цикл инкрементирует **столбец** `wr` при
  фиксированной строке `a = 1`. Слова пишутся в `%a[1][1]`, `%a[1][2]`,
  `%a[1][3]`…, тогда как `%a[N]` читает всю строку `N` (склейка столбцов), а
  `%a[2]`, `%a[3]` оказываются пустыми.
- Для сравнения: ветка `string` (`nD and 1 = 1`, строки 18072–18096) корректно
  инкрементирует **строку** `a` при `wr = 1` — разбивка по строкам даёт одномерный
  массив. Ветка `else` должна зеркалить это поведение (`Inc(a)` вместо `Inc(wr)`).
- Следствие: `get clipboard %a` для текста `мама мыла раму` даёт
  `%a[1] = "мамамылараму"`, `%a[2] = ""`, `%a[3] = ""` вместо ожидаемых слов.
  Тест `test_arr_word` в `tests/integration/clipboard_tests.txt` из-за этого
  удалён из автоматического прогона.
- Статус: не исправлено.
